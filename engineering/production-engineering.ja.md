# 05 / 公開の失敗を通常のケースとして設計する

**アクセス制御 · CI/CD · 復旧 · 本番の問題解決**

![05 / 公開の失敗を通常のケースとして設計する](../assets/diagrams/release.jpg)

## 課題

ビルド成功だけでは候補版に通信を渡せません。復旧経路も失敗します。以前、イメージタグの欠落で文書処理の旧イメージを復旧時に参照できない問題がありました。

## 私の判断

有効化前の検証、切替前後の検査、旧版の保持を要件としました。権限と公開の境界も提供の責任とし、画面だけに判断を任せません。

## 実装

検証、ビルド、候補の HTTP 検査、サービス切替、公開結果の検査を行います。切替前の失敗では現行版を保持し、切替後は復旧します。不正な公開命令を本番に触れる前に拒否するテストもあります。

## 結果と根拠

選定した命令テストで拒否入力を扱います。ソースの回帰群は候補の失敗、切替後の失敗、旧版への復旧、実行中イメージの参照保持をシミュレートします。

[release-command.test.sh](../proof/code-excerpts/release-command.test.sh) · [changelog](https://aiseek.dev/ja/changelog)

## 次の作業

ブラウザーのエラー収集は提供済みです。現行の公開経路は HTTP 検査を使い、公開前のブラウザーテストは削除されています。データベース修正は前進型のマイグレーションを使います。
