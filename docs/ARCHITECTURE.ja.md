## 構成 / 依存の方向

![AiSeek の構成：アプリケーション、ワークフロー、エンジン、データアクセス、共通の契約。依存は下位へ向かう](../assets/framework.jpg)

| 図の層 | 責任 |
|---|---|
| Applications／アプリケーション | Web と Admin は API データを表示し、API は要求を処理し、Worker はバックグラウンドの仕事を実行します。 |
| Workflows／ワークフロー | Research、フォロー、公開処理が長い仕事と公開出力を調整します。 |
| Engines／エンジン | 情報源、エンティティ、根拠、グラフ、財務の各領域を処理します。 |
| Data access／データアクセス | リポジトリ層と PostgreSQL のキューが保存状態へのアクセスを管理します。 |
| Shared contracts／共通の契約 | 型とスキーマがモジュール間の境界を定めます。 |

矢印は許される依存の方向を示し、毎回すべての層を通るという意味ではありません。上位層も共通の契約を利用します。アプリケーションをまとめても、全アプリが全バックエンドに依存できるという意味ではありません。Web と Admin は API を利用します。読みやすさのため隣接するエンジン層をまとめています。[設計の抜粋](../proof/code/frontend-boundary.test.ts)はフロントエンドの検査例です。

## 実行 / 閲覧とバックグラウンド処理

![AiSeek の実行構成：Reader、Web、API、PostgreSQL の閲覧経路。API が Worker に仕事をキューで渡し、公開、文書処理、管理された外部呼び出しを実行する](../assets/runtime.jpg)

**公開閲覧：**Web は API を通じて公開済みデータを要求します。データベース接続を開かず、モデル提供者を呼び出しません。API と PostgreSQL の線はリポジトリ層を省略した表現です。

**バックグラウンド処理：**API が長い処理をキューに入れ、Worker が実行します。Publication は公開できる出力を制御します。Document worker は文書を処理し、Model-router は呼び出し記録と予算でモデル呼び出しを管理します。図は選んだ経路を示し、他の仕事、内部のデータアクセス、応答矢印を省略しています。

**保存状態：**PostgreSQL の関係レコードが正規の記録で、グラフ投影は再構築できます。Queue は PostgreSQL を使う論理的な構成要素で、追加のキューサービスではありません。API と Worker は同じ製品にある異なる実行責任です。

実線は選定した呼び出しや書き込み、破線はキューで渡す仕事を示します。完全なネットワーク構成や全安全性の保証ではなく、責任の図です。[根拠の説明](../proof/README.ja.md)に検査範囲を示しています。

## 技術 / 責任ごとの構成

| 責任 | メイン製品の技術 |
|---|---|
| Web と Admin | TypeScript、React、React Router |
| API と Worker | TypeScript、Fastify、pg-boss |
| 正規データと検索 | PostgreSQL、pgvector、PGroonga |
| グラフ投影 | Apache AGE |
| 文書処理 | Python、FastAPI、文書処理ライブラリ |
