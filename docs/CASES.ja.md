# AiSeek を形にした三つの判断

[ポートフォリオ](../README.ja.md) · [English](CASES.md) · [中文](CASES.zh-CN.md) · [根拠](../proof/README.ja.md)

## 01 / 情報を役立つものにする

**課題。** フィードが増えても、読者の理解が深まるとは限りません。記事、主張、検証された変化は別のものです。混同すると、サイトは活発に見えても、理解する作業を読者に残してしまいます。

**私の判断。** 情報プロダクトの中心を「変化」に置きました。何が起きたか、なぜ重要か、何が支えるか、次に何を見るか。Research は補助的な機能とし、初めての読者が研究体系を理解しなくても使えるようにしました。事実、根拠のある推論、仮説を区別し、支える原文へたどれることを要件としました。

**提供したもの。** メインサイトは変化、背景記事、根拠の該当箇所、構造ビュー、継続的な読書を三言語でつないでいます。方法説明と訂正記録から、根拠の扱いを確認し、公開内容に疑問を提示できます。

**実際のトレードオフ。** 品質チェックは有用な情報を止めることもあります。公開の更新履歴には、厳しすぎる再確認ルールで主要記事の更新が滞り、その後修正された事例があります。検証は失敗しないと主張するより、この修正に意味があります。速報性と確かさの釣り合いを取り、疑義のある内容には確認の経路が必要です。

**示す能力。** プロダクトの位置づけ、情報設計、受け入れ基準、読者を損なう判断を修正する力。

**確認先：**[方法説明](https://aiseek.dev/ja/method)、[訂正記録](https://aiseek.dev/ja/corrections)、[更新履歴](https://aiseek.dev/ja/changelog)。これらは製品の挙動を説明する材料であり、事実精度のベンチマークではありません。

## 02 / 境界を検査できる形にする

**課題。** 公開閲覧、非公開の調査、外部サービスを持つシステムでは、文書上の約束だけでは不十分です。誤った依存関係が非公開の作業を漏らしたり、表示を外部呼び出し待ちにしたり、有料権限の判断をブラウザーに任せたりする可能性があります。

**私の判断。** 分離を明確な技術上の制約にしました。フロントエンドは API を読み、長い処理は非同期にし、権限はサーバーで確認し、外部呼び出しは管理された入口を通します。正規の記録と再構築できるビューには別の責任があります。成長とともに境界違反を検出できる検査を求めました。

**選定した実装の根拠：**

| 抜粋 | 示すこと | 証明しないこと |
|---|---|---|
| [サーバーの権限検査](../proof/code/server-entitlements.ts) | 要求された調査の深さをアカウントの権限以内に制限する。 | すべての認可経路の正しさ。 |
| [実行単位の予算検査](../proof/code/run-budget.ts) | 追加の予想使用量を設定された上限と比較する。 | 測定済みの費用削減や全外部呼び出しの監査。 |
| [フロントエンドの依存検査](../proof/code/frontend-boundary.test.ts) | アーキテクチャテストがバックエンドへの直接依存を拒否する。 | 完全なセキュリティ監査。 |

確認した非公開の版から、そのまま短く抜粋しています。汎用的な防御の実装を示し、製品の核心部分は公開しません。[出典一覧](../proof/source-manifest.json)。

**実際のトレードオフ。** 明確な契約と非同期処理には、一つのリクエストで全処理を行う場合より調整が必要です。その代わり、権限、失敗への対応、処理の確認に明確な置き場所ができます。複雑さがなくなるという主張ではなく、責任の分け方です。

**示す能力。** 設計判断、サーバー側の制御、資源への意識、要件を確認可能な検査に変える力。

## 03 / 公開後も責任を持つ

**課題。** 動く機能は個人プロダクトの一部分です。読者には分かる言語、使えるモバイル体験、戻る理由、誤りを知らせる手段、外部ツールとの安定した接点も必要です。

**私の判断。** 日本語・英語・中国語を製品の正式な体験として扱いました。フォロー、通知、ブリーフを再訪の流れに組み込み、訂正と連絡を利用できるようにし、アカウントの枠を持つ読み取り専用の連携機能を用意しました。更新履歴は読者に向けて変化を説明します。

**提供したもの。** 更新履歴には多言語検索の改善、モバイル対応、購読、メールブリーフ、ブラウザー通知、API/MCP が記録されています。製品は稼働状況、方法、帰属、訂正も公開しています。実際の体験はメインサイトで確認できます。

**実際のトレードオフ。** 入口が増えるほど、主張の意味と権限を保つ場所も増えます。ラベルの翻訳だけでローカライズは終わりません。約束は提供済みの範囲に限定し、測定結果は支える根拠があるときだけ示します。

**示す能力。** 一貫した提供、多言語の製品設計、運用責任、公開後の読者への継続的な配慮。

**確認先：**[サイト](https://aiseek.dev/ja)、[開発者ガイド](https://aiseek.dev/ja/developers)、[更新履歴](https://aiseek.dev/ja/changelog)、[稼働状況](https://status.aiseek.dev)。
